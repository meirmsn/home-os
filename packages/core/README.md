# @home-os/core

> Framework-agnostic Supabase client factory + prod-URL guard + shared domain types + Zod schemas. Consumed by `apps/web` directly; future Supabase edge functions consume it from the same workspace.
>
> Source-only package — exports TypeScript via `src/index.ts` with no build step (per devshop convention).

## Exports

| Export                           | Purpose                                                                                                                                                                                                                                            |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `createClient(config)`           | Framework-agnostic Supabase client factory. Apps supply prefixed env values; the factory doesn't read process.env directly.                                                                                                                        |
| `assertNotProdUrlInTestEnv(url)` | Defensive guard. Throws when `NODE_ENV=test` and the supplied URL points at the production Supabase project ref. Wired into every `createClient` call site, so any test-context misconfiguration fails loudly instead of silently writing to prod. |
| `Database` type                  | Generated by `pnpm db:gen-types` from the local Supabase stack — produces `src/supabase.types.ts`. Contains all 5 Tables + all 7 Enums. Regenerate when migrations change the schema.                                                              |
| Domain models                    | `src/models/` — shared TypeScript types for cards, photos, triage conversations, etc. Consumed by both routes and components.                                                                                                                      |

## Structure

```
packages/core/
├── src/
│   ├── index.ts              # barrel — re-exports factory, guard, models, schemas
│   ├── supabase.ts           # createClient(config) + assertNotProdUrlInTestEnv
│   ├── supabase.types.ts     # generated by pnpm db:gen-types
│   └── models/               # shared domain types (cards, triage, etc.)
├── package.json
├── tsconfig.json
└── vitest.{config,setup}.ts
```

## Why a workspace package

Per devshop convention: shared TypeScript-source packages export directly via `tsconfig` paths — no build step, no `dist/`. Consumers (currently `apps/web`) import via `@home-os/core` and pick up source changes immediately.

`createClient(config)` takes env values as parameters rather than reading `process.env` so the same package works in:

- Browser context (`apps/web/lib/supabase/client.ts` — passes `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY`).
- SSR context (`apps/web/lib/supabase/server.ts` — passes the same with Next's async `cookies()` adapter).
- Future edge functions (passing edge runtime's env shape).

This is the **workspace TS factory** pattern: framework-agnostic core + framework-specific wiring at each consumer's edge.

## Regenerating `Database` types

```bash
pnpm db:gen-types     # regenerate src/supabase.types.ts from local Supabase stack
```

Run after every migration that changes schema. The generated file is committed (the local stack may not be running for downstream consumers; the file is the contract).
