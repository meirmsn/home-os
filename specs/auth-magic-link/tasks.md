### Task 1 — vitest happy-dom JSX runtime

The dead Phase-2 implementation agent added `@testing-library/react` + `happy-dom` to `apps/web/devDependencies` and wired `environmentMatchGlobs: [['**/*.test.tsx', 'happy-dom']]` into `apps/web/vitest.config.ts`, but didn't switch the JSX transform. On first run, every `.test.tsx` rendered with React 19's automatic runtime threw `ReferenceError: React is not defined` because `tsconfig.base.json` sets `jsx: preserve` (Next's pipeline owns the transform). Resolution: add `esbuild: { jsx: 'automatic' }` to `apps/web/vitest.config.ts` so Vitest uses React 19's automatic runtime in tests without changing the Next-side TS config. `tsconfig.json` stays `jsx: preserve` so Next continues to do its own transform.

### Task 4 — sibling test instead of exempt entry for `SignInCompletedCapture.tsx`

Initial plan was to claim transitive coverage via the parent `(app)/layout.test.tsx` (mount assertion) and add an exempt-file entry. The `check-exempt-additions.sh` pre-flight tokenizer can't parse a path that contains Next route-group parens (`(app)`) — it extracts `/layout.test.tsx` as a standalone token and demands that file exist at repo root, which fails. Wrote a sibling `SignInCompletedCapture.test.tsx` instead. 4 cases lock the identify-before-capture order, the per-session no-op guard, the user.id-change re-fire, and the sessionStorage-throw silent failure. Net: stronger coverage than the exempt path, no parser workaround needed.
