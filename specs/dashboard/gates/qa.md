## Gate 9: /qa

**Mode:** Code-level review (live browser QA not feasible — requires authentication + seeded data)

**Scope:** All dashboard components under `apps/web/app/(app)/home/`

### Accessibility

| Check                                | Status      | Detail                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------ | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ARIA landmarks on dashboard sections | **finding** | No `<section aria-label="Urgent items">` / `<section aria-label="Monitoring">` wrappers. Design spec (lines 992-999) requires each tier to be a labelled section with card `<article>` elements. Implementation uses bare `<div>` with `<h2>` headings but no `aria-label` on the containing element. Cards are `<Link>` (anchor), not `<article>`. |
| Filter bar role="tablist"            | **finding** | Spec (line 999) requires `<nav aria-label="Filter by">` with `role="tablist"`. Implementation renders a `<nav>` with no `aria-label` and buttons with no `role="tab"` / `aria-selected` attributes. Screen readers see three generic buttons inside an unlabelled nav.                                                                              |
| Keyboard navigation within tiers     | **finding** | Spec (line 1059) says "Arrow keys move between cards within a tier." No `onKeyDown` handler exists on any card container. Tab-through works (links are focusable) but arrow-key navigation is absent.                                                                                                                                               |
| Card `aria-label`                    | **finding** | Spec (line 998) requires `<article>` with `aria-label="[Issue name], [Severity or state]"`. Cards render as `<Link>` (anchor) with no `aria-label`. Screen readers announce the link destination URL, not a structured label.                                                                                                                       |
| Touch targets (min 44x44)            | pass        | All interactive elements use `min-h-11` (44px). Filter tab buttons have adequate padding.                                                                                                                                                                                                                                                           |
| Focus styles                         | pass        | No `outline: none` anywhere. Default browser focus ring applies to all `<Link>` and `<button>` elements.                                                                                                                                                                                                                                            |

### Error states

| Check                              | Status      | Detail                                                                                                                                                                                                                                                                                                              |
| ---------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Supabase cards query failure       | **finding** | `page.tsx` catches `cardError` and logs to Sentry, then falls through with `cards = []`. This means a Supabase outage renders an empty dashboard (nothing-active state) with no user-visible error message. The user sees "Nothing needs a decision right now" when the real problem is a backend failure.          |
| Supabase card_photos query failure | acceptable  | `photoError` is caught and logged. Cards render with placeholder images. Degradation is graceful.                                                                                                                                                                                                                   |
| Supabase count query failure       | **finding** | The `totalCount` query (`select('id', { count: 'exact', head: true })`) does not destructure an `error` field. If the query errors, `count` is `null`, which is treated as `0` via `(totalCount ?? 0) === 0`. This would incorrectly show the first-time empty state for an existing user during a Supabase outage. |
| Signed URL generation failure      | acceptable  | If `createSignedUrl` fails, the photo is simply absent from `photoMap`. Cards render with placeholder.                                                                                                                                                                                                              |

### Edge cases

| Check                                     | Status      | Detail                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0 cards (first-time)                      | pass        | `totalCount === 0` returns `<EmptyState variant="first-time" />` with a capture CTA. Correct.                                                                                                                                                                                                                                                                   |
| 0 active cards (all closed/dismissed)     | pass        | `cards` array is empty after `.not('state', 'in', '(closed,dismissed)')`. `totalCards=0` triggers nothing-active empty state.                                                                                                                                                                                                                                   |
| 100+ cards                                | **finding** | The signed URL generation loop (`for (const row of photoRows)`) runs `await supabase.storage.createSignedUrl(...)` sequentially for each card's photo. With 100 cards, this is 100 serial async round-trips during SSR. No pagination, no `Promise.all` batching, no limit on the photo query. Page load will degrade linearly with card count.                 |
| Null severity                             | pass        | `severityChipClasses` is only called when `card.severity` is truthy. The `SeverityChipOverlay` and `SmallSeverityChip` are conditionally rendered.                                                                                                                                                                                                              |
| Null title                                | pass        | `displayTitle` falls back to `initial_description`, then to `'Untitled card'`. Tested.                                                                                                                                                                                                                                                                          |
| Null diagnosis                            | pass        | Diagnosis paragraph is conditionally rendered with `{card.diagnosis && ...}`.                                                                                                                                                                                                                                                                                   |
| Null system_tag                           | pass        | Falls back to `'other'` text in icon area. System tag badge is conditionally rendered on Tier 1.                                                                                                                                                                                                                                                                |
| Monitoring card with null next_check_at   | pass        | `tierCards` correctly excludes these from `overdueMonitor`. Tested.                                                                                                                                                                                                                                                                                             |
| Walkthrough with 0 overdue cards          | pass        | `WalkthroughPrompt` returns null when `overdueCount === 0`. Walkthrough button is conditionally rendered.                                                                                                                                                                                                                                                       |
| Card with `chosen_path: 'monitor'`        | **finding** | The PLANNED chip in `DashboardCard` shows `planned - diy` for any `chosen_path` that is not `'contractor'`, including `'monitor'`. This is a semantic mismatch -- a card with `chosen_path: 'monitor'` was routed to monitoring, not DIY. The ternary `card.chosen_path === 'contractor' ? 'contractor' : 'diy'` should handle the `'monitor'` case explicitly. |
| `tier2` cards always show "Overdue" label | **finding** | The `tier2` variant in `DashboardCard` unconditionally renders `<p>Overdue</p>`. However, the `tier2` tier is used in `AllTab` for all monitoring cards regardless of overdue status. A fresh monitoring card viewed on the "All" tab would incorrectly show "Overdue".                                                                                         |

### Summary

**Findings: 8** (4 accessibility, 2 error handling, 2 edge case)

The accessibility gaps are the most significant cluster. The implementation is functional but does not match the ARIA landmark and keyboard navigation patterns specified in the design review. The error handling gap around the count query is a latent bug that would surface during Supabase outages. The sequential signed URL generation is a scalability concern (see Gate 10 for detailed analysis).
